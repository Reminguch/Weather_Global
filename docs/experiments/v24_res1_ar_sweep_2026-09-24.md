# AR horizon sweep, 2026-09-24

The selected recipe is the 1-degree v24 residual GraphCast/Mamba model with
width 512, d_inner 16, BCG1, Mamba1 initialization, and the original frozen
GraphCast-small backbone. Submit K=1,4,8,12,16 independently.

## Why this recipe

The September batch-4 fast-Mamba SWA run has the best observed exact original
GraphCast rollout-loss reduction among the compared completed optimizer/LR
recipes: **16.343%** over 32 matched 2022 origins and 40 six-hour leads;
day-10 reduction is **23.683%**. Its final checkpoint scored 15.264%.
The d_inner=32 joint-SWA run is close at 16.294%; that 0.05-point difference
does not establish a statistically reliable advantage. d_inner=16 is the
smaller choice. The old LR campaign also used independently trained warmups,
so its rankings should be treated as observed recipe comparisons.

The recovered 8k spatial-LR campaign reaches at most 14.776% with SWA, and
the fresh width-512 constant-LR 20k run reaches 4.013% with its late SWA.
The width-128 K20 finetune reaches 10.829% with SWA. The recovered FP32-MSE
pair reaches 15.570%, while AMSE is near zero. These results do not justify
choosing the longer or alternative-loss recipes for this sweep.

## Fixed training recipe

| Setting | Choice |
|---|---|
| Resolution, backbone | 1 degree, original frozen GraphCast-small, mesh5, width512, MP16 |
| Trainable correction | Width512, MP2, Mamba1 d_inner16/d_state16/d_conv4, two layers, BCG1 |
| Initialization | Baseline overlay, temporal zero output, seed22; each arm uses its K from its first update |
| First stage | 500 updates, AdamW, common peak LR 1e-4, 50-update linear ramp then constant |
| Second stage | 2,000 updates, optimizer reset, zero recurrent state, spatial peak LR 1e-4, Mamba peak LR 3e-4 |
| Second-stage schedule | 50-update ramp, then cosine to spatial 1e-5 / Mamba 3e-5 |
| AdamW | beta1=0.9, beta2=0.98, weight decay=1e-4, global gradient clipping=1.0 |
| Batch and sequence | Batch4, BPTT24, segment96, state carried, closed-loop stop-gradient weather feedback |
| Objective and precision | Original all-step MSE, BF16 model arithmetic, FP32 weather tape |
| Primary SWA | Equal average of branch updates 500/1000/1500/2000 (total updates 1000/1500/2000/2500) |
| Total budget | 2,500 updates per arm; 240,000 supervised sample-steps; independent three-update numerical smoke excluded |

No K20-trained checkpoint initializes these runs. The two-stage schedule
reproduces the selected recipe, including the first stage's common learning
rate and the second stage's optimizer/RNG/cursor reset. The initialization
procedure and seed are fixed; bitwise identity across different GPU jobs is
not asserted.

K follows the existing repository scan convention. K1 uses `ar_tail_k=0`
(teacher forcing); K4/8/12/16 use tails 4/8/12/16. With this historical
convention, the longest forecast chain is tail+1. Every arm retains 24
supervised positions per chunk, so changing K changes the teacher-forced
prefix and AR tail while retaining the same recurrent gradient horizon.
This is an AR-tail ablation at fixed BPTT, not a change in BPTT length.

Each GPU task first runs a separate three-update smoke and checks finite
loss/parameters, batch size, and checkpoint/configuration roundtrip. Only
then does it run the two production stages and build SWA. Source, vendored
GraphCast, configurations, baseline, statistics, anchor manifests and
evaluation metadata are pinned before submission.

## Evaluation and resources

Evaluate the first-stage checkpoint, final branch checkpoint and prescribed
SWA against the same 32 origins, with a 40-step cold full-feedback rollout
and zero recurrent state. Use each evaluation's own paired baseline; report
the ratio after aggregating exact losses across origins and leads. The
primary comparison is the fixed SWA, with final checkpoints as diagnostics.
The 2022 origins are a development comparison, not an untouched test set.

Training array: five unthrottled tasks, one 80GB GPU, eight CPUs, 320GiB CPU
RAM and 36 hours each. Completed jobs 13740084_6-9 took 20:10-22:41; comparable
batch4 jobs reached approximately 235GiB RSS. Fixed BPTT24 keeps the model
work similar, while shorter AR tails require more truth frames. The request
adds room for that loading and the smoke. Approximate total training use is
110 GPU-hours, with 180 GPU-hours reserved by the limits.

Evaluation array: five tasks, one 80GB GPU, eight CPUs, 16GiB CPU RAM and
4.5 hours each, using corresponding successful training-task dependencies.
Recovered evaluations 14246322_0-5 took 3:06-3:20 and peaked around 9.4-10GiB.
The dependent CPU report gets one CPU, 4GiB and 15 minutes.
